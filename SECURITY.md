# Security policy

## Supported code

Security fixes are currently developed against the latest code on `main`. Older snapshots and forks have no separate security maintenance commitment.

## Report a vulnerability

Use GitHub's [Report a vulnerability](https://github.com/JacobScheff/Locked/security/advisories/new) form to send a private report to the maintainer. This requires private vulnerability reporting to be enabled for the repository.

If the form is unavailable, use a private contact method published on [JacobScheff's GitHub profile](https://github.com/JacobScheff). If none is listed, open an issue requesting a private security contact **without including vulnerability details**. Do not post exploit steps, credentials, cookies, or student information in a public issue or pull request.

Include the affected commit or version, iOS and Xcode versions where relevant, a description of the impact, and a minimal reproduction using synthetic data. State whether the issue concerns school authentication, local storage, Screen Time authorization, or app/extension communication. Remove personal data and live credentials from all attachments.

The maintainer will assess reports as availability allows. There is no guaranteed response deadline or bug bounty. Please coordinate public disclosure with the maintainer so a fix can be prepared.
